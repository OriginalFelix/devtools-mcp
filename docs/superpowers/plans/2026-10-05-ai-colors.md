# Eigene Farbe und eigener Zustand je KI – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jede MCP-Session bekommt eine eigene Farbe (größte Lücke auf dem Farbkreis) und einen eigenen Fensterzustand (Bindung, Overlay, Zeiger).

**Architecture:** `ToolSession` (core) trägt Session-ID und Client-Name durch den Aufruf. `WindowSessions` hält je Session eine `WindowSession` mit Farbe aus `AiColors`, Overlay und Geräten; `WindowSupport` holt die Session je Aufruf. Die Farbe reicht über `CursorController.create(x, y, Color)` bis in die nativen Zeigerfenster.

**Tech Stack:** Java 25, Swing (Overlay), JNA (natives), JUnit 5 + AssertJ. Spec: `docs/superpowers/specs/2026-10-05-ai-colors-design.md`.

## Global Constraints

- Farbton HSB(h, 1, 1); Vergabe größte Lücke, erste KI 0°, bei Gleichstand erste Lücke ab 0°.
- Session ohne MCP: ID `local`; Client-Name ohne `clientInfo`: „KI“.
- Leerlauf bis zum Aufräumen einer Session: 30 Minuten; Zeiger-Leerlauf (60 s) bleibt.
- Konfliktmeldung: „<Prozess> wird gerade von <Client> gesteuert.“
- Deutsch in Texten/Kommentaren; Commits lokal, Push nur auf Anweisung.
- Java-Dateien mit Backslashes per Write/Edit schreiben (Shell verschluckt `\`).
- Tests: `./gradlew :natives:test`, `./gradlew :desktop:test --tests '<Filter>'`.

### Task 4: WindowSession und WindowSessions

**Files:** Modify `WindowSession.java`; Create `WindowSessions.java`; Test `WindowSessionsTest.java`.

**Produces:**
- `WindowSession(String id, String client, Color color, Function<Binding, Optional<String>> conflict)`; bisheriger Konstruktor `WindowSession()` → `("local", null, CursorImage.ACCENT, b -> Optional.empty())`.
- `String client()` („KI“ wenn null), `Color color()`, `<T> T resource(String key, Supplier<T> factory)`, `void close()` (unbind; Ressourcen, die `AutoCloseable` sind, schließen; Fehler loggen).
- `bind(Binding)` prüft vorher `conflict` → `IllegalStateException(reason)`.
- `WindowSessions(AiColors colors, Duration idle, LongSupplier clock)`; `WindowSession current()` (aus `ToolSession.current()`, legt an, merkt Zeitpunkt); `void reap()` (Sessions älter als idle schließen, Farbe freigeben); `int size()`; Standard-Instanz plant `reap` jede Minute auf einem Daemon-Thread (`start()`), `close()` beendet.
- Konflikt: andere Session mit Bindung `o`, wenn `o.pids(false).contains(neu.process().pid())` oder `neu.pids(false).contains(o.process().pid())` → „<neu.name> wird gerade von <client> gesteuert.“

- [ ] Tests: zwei Sessions (`ToolSession.callIn`) → verschiedene Farben (0° und 180°); Session s2 bindet Testprozess, den s1 gebunden hat → Exception mit „wird gerade von“; gleiche Session darf neu binden; `reap()` nach Uhr + 31 min → `size()==0`, neue Session bekommt wieder 0°.
- [ ] Commit `feat(window): eigener Fensterzustand je KI`.
